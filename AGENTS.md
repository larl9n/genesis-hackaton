# Контекст для продолжения работы

Перед работой прочитай [docs/PROJECT_CONTEXT.md](docs/PROJECT_CONTEXT.md), затем [README.md](README.md) и документы, относящиеся к изменению. Последние указания пользователя имеют приоритет над сохранённым контекстом.

- Общайся с пользователем по-русски.
- Команда участвует в Genesis Hackathon; нужен проект по кейсу RL-среды финансового аудита.
- Пользователь разрешил переход к технической реализации по этапам. После каждого этапа выполняй необходимые функциональные проверки; фиксируй результат и ограничения до перехода дальше.
- Не распределяй задачи между участниками: пользователь отменил это пожелание.
- Отдельный сайт необязателен; дизайн отложен.
- Отличай работающий код от описанной архитектуры. Не заявляй готовность среды, обучения модели, изоляции, CI или публикации без проверки.
- Не придумывай Git-авторство и не используй force push. Перед публикацией проверь удалённую историю и обычный доступ.
- При существенном изменении состояния обновляй `docs/PROJECT_CONTEXT.md`.
- `docs/CHAT_HISTORY.md` — локальный снимок видимой переписки. Он не должен автоматически попадать в публичный репозиторий.
