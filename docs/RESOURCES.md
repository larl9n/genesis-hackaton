# Ресурсы и область измерения

Контейнер ограничен 1 CPU, 512 MiB RAM без дополнительного swap, 64 PID, 128 FD и tmpfs 64 MiB. Supervisor запускает workers последовательно. 100 шагов и 60 секунд контролируются отдельно; зависание проверяется реальным Docker-тестом.

До удаления контейнера фиксированный Python reader под UID65534 читает kernel cgroup v2: memory.peak, memory.max, cpu.stat usage_usec, memory.events oom_kill. Сам reader входит в пик. Значения не берутся из сообщений политики. Если Linux не предоставляет эти counters, corpus evaluator завершится ошибкой, а не объявит измерение успешным. Данные reader не передаются политике.

[Проверка блока C](https://github.com/larl9n/genesis-hackaton/actions/runs/43588561164), Linux Ubuntu 24.04 / Python 3.11.18: 80 основных прогонов (60 контейнерных + 20 host oracle), 80 точных повторов, 20 grader-пар. Все контейнерные resource gates прошли, OOM=0. Максимальный worker peak **25 141 248 bytes (≈24.0 MiB)**, supervisor RSS peak **30 412 800 bytes**, дочерний CLI RSS peak **29 290 496 bytes**. Самый долгий основной worker-run **0.376 s**; весь корпус с replay и валидацией — **53.0 s**. Эти числа зависят от CI-хоста и версии, новый отчёт записывает новые замеры.

RSS peaks и worker peak — разные измерения. Их сумма может служить грубой консервативной оценкой компонентов приложения, но не одновременным пиком всей системы. Docker daemon, ядро, cache других процессов и ОС хоста не включены. Запуск на физически ограниченном хосте 2 CPU / 4 GB целиком не сертифицирован; предлагаемый бюджет черновика не следует выдавать за утверждённый регламент. Аппаратных данных официального стенда нет.
