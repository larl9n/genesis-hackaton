# Единый оценочный запуск

```bash
PYTHONPATH=src python -m genesis_fintech evaluate-dataset artifacts/public-corpus-v1 --output artifacts/corpus-evaluation --replay
```

Требуется заранее собранный Docker worker image. По умолчанию три обычные политики запускаются отдельными контейнерами без mounts/сети; oracle исполняется только в доверенном оценщике. Явный `--backend development` предназначен только для доверенной локальной проверки IPC. Отсутствие Docker не переключает режим автоматически.

Оценщик читает сохранённые public/truth, не пересоздаёт данные из seed. Для всех четырёх стратегий используются одинаковые записи, их SHA-256 сохраняется в отчёте. У каждого нового worker чистое состояние; seed политики независим от генератора. Начальные данные и все ответы передаются только через узкий JSON-интерфейс.

## Выполняемые проверки conformance-v1

1. Валидация всех 20 файловых эпизодов: hashes, размеры, версии, независимая проверка эталона и доказательств.
2. 80 прогонов: конечная валидная отправка, до 100 шагов, без ошибок инструментов и truncation. Низкий F1 слабой политики не является сбоем протокола.
3. Все observations и нулевые evaluation rewards проверяются на запрещённые приватные поля.
4. Каждая сохранённая отправка повторно оценивается независимым public-record entry point; score должен точно совпасть с отчётом среды.
5. Oracle должен находить все метки с F1=1; flag-all должен быть хуже oracle.
6. Для каждого из 20 эпизодов grader проверяется после обратимого переименования IDs и перестановки записей. Сохраняется оценка обоснованных oracle findings при одинаковой стоимости действий. Это grader-пары, не 20 дополнительных полноценных запусков worker.
7. `--replay` дополнительно пересоздаёт corpus и повторяет все 80 прогонов. Метрики и траектории совпадают точно; runtime сравнивать побайтово нельзя.
8. После завершения повторно проверяется целостность исходного корпуса.

`report.json` содержит результаты каждого прогона, сводные precision/recall/F1, награды, шаги, диагностику ошибок и ресурсы; report.md — краткую таблицу. conformance.json фиксирует проведённые проверки, trajectories.jsonl — реальные действия/наблюдения. Полные результаты принадлежат оценщику; они не входят в интерфейс политики.

## Что измерено и что не обещаем

RSS supervisor и дочернего CLI измеряются отдельно; это не суммарная память системы и Docker daemon. Для Docker записан лимит worker 512 MiB и неизменяемый image ID. Финальные аппаратные измерения и упаковка — отдельный блок. Наш набор проверок не является официальным стендом организаторов и не утверждает улучшение LLM.

Локальный development-прогон 20 эпизодов: reconciliation/oracle TP72/FP0/FN0, все 4 чистые компании без ложных тревог. Random TP0/FP80/FN72; flag-all TP8/FP592/FN64, micro F1≈0.02381. Это результат на публичном ограниченном синтетическом корпусе, не доказательство обобщения на неизвестные реальные данные.
