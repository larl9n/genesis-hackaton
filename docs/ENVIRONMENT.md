# Контракт среды v0.1

Статус: предлагаемый контракт, реализация отсутствует. [Типы Python](../src/genesis_fintech/contracts.py) фиксируют форму обмена, но не проверяют JSON во время выполнения.

## Управляющий API

```python
observation, info = env.reset(seed, config)
observation, reward, terminated, truncated, info = env.step(action)
```

Это API управляющего процесса в стиле Gymnasium. Политика в режиме оценки видит только сериализованные наблюдения. Seed и полная конфигурация не передаются политике. Наследование от Gymnasium Env пока не требуется.

Начальное наблюдение содержит задачу, публичный manifest, краткую policy и оставшийся бюджет. Последующие — запрошенные записи, результат инструмента либо ограниченную ошибку, остаток шагов. В `info` для политики нет эталона, диагностики scorer, приватных путей и stack trace.

## Формат действий

Предлагаем единую оболочку:

```json
{"action": "list_records", "params": {"table": "ledger", "cursor": null, "limit": 50}}
```

| Действие | Параметры | Результат |
| --- | --- | --- |
| `list_records` | `table`, `cursor`, `limit` | Страница до 50 записей и следующий стабильный курсор |
| `get_record` | `table`, `id` | Одна открытая запись |
| `get_document` | `doc_id` | Один открытый документ |
| `calculator` | `expression` | Результат ограниченной десятичной арифметики |
| `submit` | `episode_id`, `findings` | Завершение эпизода; в evaluation без оценки для политики |

Таблицы: `ledger`, `invoices`, `payments`, `fx`. Точные правила ID для FX и сериализации курсоров нужно зафиксировать до реализации. Разрешённые операции калькулятора: `+`, `-`, `*`, `/`, скобки и знаки чисел. Ограничить длину выражения, число узлов, глубину и размер чисел; не применять `eval` или исполнение Python. Деление на ноль возвращает ограниченную ошибку и расходует шаг.

## Бюджет и завершение

- До 100 шагов суммарно, включая отправку; неверное действие расходует шаг.
- На последнем доступном шаге допустимый `submit` завершает эпизод успешно как действие. Если шаг потрачен на исследование и бюджет исчерпан, результат — truncation с пустой отправкой.
- `submit`: `terminated=true`, `truncated=false`.
- Лимит шагов или времени: `terminated=false`, `truncated=true`, итоговые findings пусты.
- Предлагаемый wall-time — 60 секунд на взаимодействие после выдачи начального наблюдения; фактический таймер измеряется монотонными часами. Этот выбор нужно согласовать с итоговым регламентом.
- Действия после завершения не меняют траекторию, находки или награду; точную форму ошибки нужно закрепить при реализации.
- Каждый `reset` создаёт изолированное состояние и новый бюджет.

## Находки

Пример формы; ID иллюстративные, это не готовый эпизод:

```json
{
  "action": "submit",
  "params": {
    "episode_id": "episode-example",
    "findings": [
      {
        "type": "duplicate_invoice",
        "affected_ids": ["row-example-1", "row-example-2"],
        "claimed_amount_minor": 10000,
        "currency": "KZT",
        "evidence_ids": ["row-example-1", "row-example-2", "doc-example"],
        "explanation": "Две проводки отражают один и тот же подтверждённый счёт."
      }
    ]
  }
}
```

До 30 находок, 10 evidence ID и 1000 символов объяснения на находку. Сумма — целое число минимальных единиц валюты. Краткое объяснение поддерживает вывод; награда не оценивает убедительность текста.

## Сопоставление и награда

TP требует правильного типа, канонических affected IDs, суммы в допустимых пределах, валюты и хотя бы одного полного допустимого набора доказательств. Одна истина и один вывод сопоставляются максимум один раз. Несопоставленные и повторные выводы — FP, несопоставленные истинные ошибки — FN.

```text
P  = TP / (TP + FP), при нулевом знаменателе 0
R  = TP / (TP + FN), при нулевом знаменателе 0
F1 = 2*TP / (2*TP + FP + FN)
reward = clip(2*F1 - 1 - 0.002*inspection_steps, -1, 1)
```

Если истина и выводы пусты, F1=1; если истина пуста, а выводы нет, F1=0. Шаги исследования включают действия до `submit`, в том числе ошибочные; сама отправка не является inspection step. Невалидная отправка завершает эпизод с оценкой -1 в логе оценщика.

Исследовательские награды равны нулю. В train терминальная награда доступна политике. В evaluation значение возвращается управляющему процессу, а мост отфильтровывает награду и диагностику из ответа политике до завершения всего прогона. Формат публичной траектории в evaluation должен учитывать это различие.

Канонизация, правила округления, выбор сопоставления при неоднозначности и параметры лимитов должны быть реализованы и опубликованы до оценки. Пока эта документация не является работающим grader.
