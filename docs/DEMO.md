# Демонстрация кейса

Подготовить Python 3.11 и Docker image по RELEASE.md до выступления. Все данные синтетические; ни API-ключ, ни GPU не нужны.

1. Кратко объяснить: агент проверяет записи, запрашивает доказательства и отправляет структурированные находки. Закрытый эталон проверяется по открытым документам независимым кодом.
2. Показать `configs/interactions.json`: четыре семейства, взаимодействия FX+allocation и duplicate+cutoff; partial/split/refund и границы периода создают корректные отвлекающие случаи.
3. Выполнить настоящий внешний прогон:

```bash
PYTHONPATH=src python -m genesis_fintech run-policy --seed 42 --config configs/interactions.json --output artifacts/presentation-run
```

Для этого фиксированного примера reconciliation: TP4/FP0/FN0, F1=1, 12 действий, reward0.978. Открыть summary.json и trajectories.jsonl: reward политики равен нулю, итоговая оценка находится у supervisor. Папка должна быть новой.

4. Показать полный `report.md` из `make evaluate`: random и flag-all дают ложные тревоги/пропуски; reconciliation на публичных 20 эпизодах достигает TP72/FP0/FN0, oracle показывает достижимый потолок. Это не обучение модели и не результат на неизвестных данных.
5. Объяснить Docker: сеть и mounts отсутствуют, worker не содержит генератор/оценщик, отдельные UID/лимиты; cgroup counters и cleanup проверяются в CI. Защита доверяет ядру и Docker.

Дополнительный UI: `PYTHONPATH=src python -m genesis_fintech serve`, затем http://127.0.0.1:8765. Это доверенная локальная демонстрация, она не заменяет контейнерную оценку. На обязательный кейс сайт не влияет.

Для сдачи приложить source bundle/wheel + SHA256SUMS, ссылку на проверенный commit/CI и отчёт. Прежде чем отправлять организаторам, сверить актуальный регламент, формат приёма и точное время дедлайна.
